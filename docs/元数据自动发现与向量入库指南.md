# 元数据自动发现与向量入库指南

本文说明：**如何自动识别 Hive 里有哪些表**，**如何提取元数据写入 L1**，**如何构建向量库索引**。

---

## 1. 总流程

```text
Hive Metastore / JDBC
        │
        ▼  ① 自动发现（库、表、字段、注释、分区）
   sync_hive_metadata.py
        │
        ▼  ② 写入 L1 元数据库（MySQL）
   table_meta / column_meta
        │
        ▼  ③ 人工补全（可选但强烈建议）
   description / synonyms / JOIN / metric
        │
        ▼  ④ 生成 embed 文本 + embedding
   build_vector_index.py
        │
        ▼  ⑤ upsert 向量库 + 写 vector_index_log
   Milvus / Qdrant
```

**要点：向量库的内容来自 L1/L2，不是直接从 Hive 业务表抽数据行。**

## 2. 自动发现 Hive 表：三种方式

### 方式 A：PyHive + DESCRIBE（简单，MVP 推荐）

适合：有 HiveServer2，能执行 `SHOW TABLES` / `DESCRIBE`。

```python
from pyhive import hive

conn = hive.connect(host="hive-server", port=10000, database="default")
cursor = conn.cursor()

# 1. 列出库（若权限允许）
cursor.execute("SHOW DATABASES")
databases = [row[0] for row in cursor.fetchall()]

target_dbs = ["ods", "dwd", "dws"]  # 只同步问数相关库

for db in target_dbs:
    cursor.execute(f"USE {db}")
    cursor.execute("SHOW TABLES")
    for (table_name,) in cursor.fetchall():
        cursor.execute(f"DESCRIBE FORMATTED {db}.{table_name}")
        rows = cursor.fetchall()
        # 解析 col_name, data_type, comment
        # 解析分区字段 Partition Information
```

**优点**：不依赖 Metastore 直连，部署简单。  
**缺点**：逐表 DESCRIBE，表多时要分批 + 限速。

### 方式 B：Hive Metastore（MySQL）直连（表多时推荐）

Hive Metastore 本身通常是 MySQL/PostgreSQL，存了全部表结构。

```sql
-- 表列表
SELECT d.NAME AS db_name, t.TBL_NAME AS table_name, tp.PARAM_VALUE AS comment
FROM TBLS t
JOIN DBS d ON t.DB_ID = d.DB_ID
LEFT JOIN TABLE_PARAMS tp ON t.TBL_ID = tp.TBL_ID AND tp.PARAM_KEY = 'comment'
WHERE d.NAME IN ('ods', 'dwd', 'dws');

-- 字段列表
SELECT d.NAME AS db_name, t.TBL_NAME AS table_name,
       c.COLUMN_NAME, c.TYPE_NAME, c.COMMENT
FROM COLUMNS_V2 c
JOIN SDS s ON c.CD_ID = s.CD_ID
JOIN TBLS t ON s.SD_ID = t.SD_ID
JOIN DBS d ON t.DB_ID = d.DB_ID
WHERE d.NAME IN ('ods', 'dwd', 'dws')
ORDER BY d.NAME, t.TBL_NAME, c.INTEGER_IDX;
```

**优点**：一次 SQL 拉全量，速度快。  
**缺点**：需 Metastore 只读账号；不同 Hive 版本表名可能略有差异。

### 方式 C：JDBC + information_schema 类接口

部分发行版（如某些云 Hive）提供 `information_schema.tables/columns`，用法类似 MySQL。

## 3. 同步到 L1 元数据库

脚本：`scripts/sync_hive_metadata.py`

### 3.1 同步规则

| Hive 字段 | 写入 L1 |
|-----------|---------|
| database | `table_meta.db_name` |
| table | `table_meta.table_name` |
| table comment | `table_meta.hive_comment` + 若 `description` 空则填入 |
| column | `column_meta.column_name` |
| column type | `column_meta.data_type` |
| column comment | `column_meta.hive_comment` + 若 `description` 空则填入 |
| 分区字段 | `column_meta.is_partition=1`，`table_meta.partition_cols` |

### 3.2 ID 生成策略

```python
def make_table_id(db: str, table: str) -> str:
    return f"T_{db}_{table}".replace(".", "_")

def make_column_id(table_id: str, column: str) -> str:
    return f"{table_id}__{column}"
```

### 3.3 Upsert 逻辑

```text
Hive 有、L1 无  → INSERT，is_enabled=1
Hive 有、L1 有  → UPDATE hive_comment/data_type/synced_at（不覆盖人工 description）
Hive 无、L1 有  → is_enabled=0（软下线，不物理删除）
```

**绝不覆盖**：人工填写的 `description`、`synonyms`、`cn_name`、`domain`。

## 4. 构建向量索引

脚本：`scripts/build_vector_index.py`

### 4.1 哪些对象要 embed

| object_type | 来源表 | embed 文本构成 |
|-------------|--------|----------------|
| `table` | table_meta | 库表名、中文名、description、domain、sample_questions |
| `column` | column_meta + table_meta | 表说明 + 字段名 + 类型 + description + synonyms |
| `metric` | metric_def | 指标名、aliases、definition、related_tables |
| `join` | table_relation | 左右表字段、join_type、description |
| `doc_chunk` | kb_chunk + kb_document | 文档标题 + chunk 正文 |

### 4.2 embed 文本模板（字段示例）

```text
表：ods.dim_user（用户维度表）
字段：age
类型：int
含义：用户年龄，周岁
同义词：年纪, 岁数
主题域：用户
```

### 4.3 增量更新

```python
import hashlib

def text_hash(text: str) -> str:
    return hashlib.sha256(text.encode("utf-8")).hexdigest()

# 对每个 object：
#   new_hash = text_hash(embed_text)
#   old_hash = vector_index_log.embed_text_hash
#   if new_hash != old_hash → re-embed 并 upsert
#   if L1 is_enabled=0 → 从向量库 delete
```

### 4.4 向量库写入

```python
point = {
    "id": f"column:{column_id}",
    "vector": embed(embed_text),
    "payload": {
        "object_type": "column",
        "object_id": column_id,
        "db": db_name,
        "table": table_name,
        "column": column_name,
        "domain": domain,
    }
}
vector_db.upsert(point)
```

## 5. 定时任务建议

| 任务 | 频率 | 命令 |
|------|------|------|
| Hive → L1 同步 | 每天 02:00 | `python scripts/sync_hive_metadata.py` |
| L1/L2 → 向量库 | 同步后立刻 / 每小时 | `python scripts/build_vector_index.py` |
| 全量重建 | 每周 | `python scripts/build_vector_index.py --full` |

## 6. 人工补全清单（同步后必做）

自动发现**只能**拿到 Hive 注释，上线问数前建议对核心表补：

- [ ] `table_meta.cn_name`、`domain`
- [ ] `column_meta.description`（注释太短时重写）
- [ ] `column_meta.synonyms`
- [ ] `table_relation`（多表 JOIN）
- [ ] `metric_def`（DAU/GMV 等）
- [ ] `synonym`（会员、日活等口语）
- [ ] L2 上传指标白皮书并切 chunk

## 9. 常见问题

**Q：能否跳过 MySQL，直接向量化 Hive 注释？**  
A：可以跑通 demo，但无法维护 JOIN/指标/同义词/权限，不适合生产。

**Q：Hive 表几千张都要进向量库吗？**  
A：不必。按 `domain` 或表白名单过滤，MVP 先同步 10–30 张核心表，`is_enabled=1` 才 embed。

**Q：向量库和 MySQL 不一致怎么办？**  
A：以 MySQL 为真相源，定期 `--full` 重建；`vector_index_log` 做增量对账。

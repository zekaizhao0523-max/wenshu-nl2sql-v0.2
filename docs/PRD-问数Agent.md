## 1. 背景与问题

业务同学和分析师日常取数高度依赖「提需求 → 等数仓/数据同学写 SQL → 反复确认口径 → 出数」。常见痛点：

- **响应慢**：简单取数也要排队，小时到天级延迟。
- **口径不一致**：同一指标多人多口径，结果不可复用。
- **门槛高**：业务不会写 SQL，分析师要熟悉数百张表。
- **风险高**：直接连生产库、误写语句、越权查敏感受控数据。

**问数**要解决的核心问题：用自然语言完成「找表 → 写 SQL → 沙箱验证 → 安全出数」，并在可审计、可解释的前提下缩短取数周期。

---

## 2. 产品定位与目标

### 2.1 一句话定位

问数是面向企业内部的 **NL2SQL 智能取数 Agent**：用户用自然语言描述取数需求，系统自动定位相关表与字段、生成只读 SQL、在沙箱中验证后返回结果，并附带口径说明与可追溯审计。

### 2.2 产品目标

| 目标 | 说明 | 成功标准（MVP） |
|------|------|----------------|
| 提效 | 高频简单/中等复杂度取数自助完成 | 目标场景平均端到端耗时 &lt; 60s |
| 准确 | 选表、SQL、结果口径可控 | 黄金集结果正确率 ≥ 70%（MVP） |
| 安全 | 只读、限权、可审计 | 0 次写库事故；100% 请求有审计 |
| 可解释 | 用户能理解「怎么算出的」 | 每次回答附带 SQL + 口径说明 |

### 2.3 非目标（本期不做）

- 自动写入业务库 / 自动建数仓模型
- 替代完整 BI 可视化平台（复杂看板、订阅报表）
- 跨公司公有云多租户 SaaS 售卖（先做企业内私有化/专有云）
- 完全无人值守的财务级强合规出数（需人审链路）

## 3. 用户与场景

### 3.1 用户角色

| 角色 | 诉求 | 典型行为 |
|------|------|----------|
| 业务同学 | 要数、要结论，不关心 SQL | 「昨天付费用户有多少」 |
| 数据分析师 | 要快出草稿 SQL，可改可验 | 「先帮我写一版，我再调」 |
| 数据开发 / 数仓 | 维护口径、表结构、权限 | 配置指标字典、审核高频 SQL |
| 管理员 | 权限、审计、成本、稳定性 | 看谁查了什么、限流、关功能 |

### 3.2 核心场景（User Stories）

1. **过滤取数**：作为业务，我想查「年龄 &gt; 30 的用户列表」，以便做运营圈选。
2. **指标查询**：作为业务，我想查「某天 GMV / DAU」，以便做日报核对。
3. **多表关联**：作为分析师，我想查「某渠道注册用户的首单转化」，以便做漏斗分析。
4. **二次追问**：作为用户，我想在上一次结果上继续问「按城市拆开」，以便下钻。
5. **口径确认**：当指标定义不清时，系统应追问或列出候选口径，避免瞎猜。
6. **人审出数**（可选开关）：敏感指标需分析师确认 SQL 后再跑全量。

### 3.3 场景优先级

| 优先级 | 场景 | MVP |
|--------|------|-----|
| P0 | 单表过滤取数、基础指标查询 | ✅ |
| P0 | Schema 检索 + SQL 生成 + 沙箱执行 | ✅ |
| P0 | 只读安全与审计 | ✅ |
| P1 | 多表 JOIN、会话追问、指标语义层 | ✅/部分 |
| P2 | 结果图表、定时订阅、飞书/企微机器人 | ❌ |
| P2 | 自动训练/持续学习闭环平台化 | ❌ |

## 4. 产品范围与版本规划

### 4.1 MVP（v0.1）

- 对话式问数（Web）
- 基于元数据的表/字段召回
- LLM 生成只读 SQL
- 静态校验 + 沙箱试跑（LIMIT 预览）
- 返回：结果表、SQL、自然语言解释、口径/假设
- 基础权限（按库/表白名单）+ 全量审计日志
- 内部黄金集评测（≥ 50 题）

### 4.2 v1.0

- 指标语义层（官方指标优先于临时拼 SQL）
- 多轮追问与上下文记忆
- 行列级权限与脱敏
- 人审工作流（敏感查询）
- 反馈闭环（点赞/纠错 → few-shot）
- 管理后台：元数据、指标、权限、评测看板

### 4.3 后续

- 机器人入口、定时问数、结果订阅
- 血缘展示、查询成本预估
- 多引擎（PG / MySQL / ClickHouse / Hive/Spark SQL）

## 5. 功能需求

### 5.1 功能全景

```text
问数对话
  ├─ 意图识别与澄清追问
  ├─ Schema / 指标检索
  ├─ SQL 生成与自愈
  ├─ 沙箱执行与结果展示
  └─ 导出 / 分享（权限内）

知识与治理
  ├─ 表字段元数据管理
  ├─ 指标字典 / 语义层
  ├─ 同义词与 JOIN 知识
  └─ Few-shot / 评测集管理

安全与运营
  ├─ 认证授权
  ├─ 行列脱敏
  ├─ 审计日志
  └─ 限流 / 配额 / 开关
```

### 5.2 功能详述

#### F1. 对话式问数（P0）

| 项 | 说明 |
|----|------|
| 描述 | 用户输入自然语言，系统返回结构化取数结果 |
| 输入 | 文本问题；可选：指定数据集/主题域 |
| 输出 | 答案摘要、结果表（预览）、SQL、口径说明、执行状态 |
| 规则 | 支持打断重问；支持「换一种写法」；展示耗时与行数 |
| 异常 | 无法理解 → 追问；无权限 → 明确拒绝；多次失败 → 转人工指引 |

#### F2. 意图识别与槽位抽取（P0）

系统需识别至少以下意图：

- `data_query`：取数
- `metric_query`：指标查询
- `meta_query`：问表/字段含义
- `chitchat`：非取数（引导回主流程）

需抽取槽位：时间范围、对象实体、指标名、过滤条件、分组维度、排序/TopN、输出粒度。

**验收**：缺失关键槽位（如无时间却问「昨天」类指标）时必须追问，不得直接瞎跑。

#### F3. Schema 检索（P0）

| 项 | 说明 |
|----|------|
| 描述 | 根据问题召回相关表、字段、关系 |
| 能力 | 关键字 + 向量检索；返回 Top-K；可展开表详情 |
| 约束 | 仅召回用户有权限的对象；prompt 中只注入召回子集 |

#### F4. 指标字典 / 语义层（P1，MVP 可先做轻量版）

- 指标名、别名、官方 SQL/表达式、负责人、适用表
- Agent 命中官方指标时 **优先使用官方定义**，并在回答中标注「官方口径」
- 未命中时允许临时生成，但必须标注「临时推导，请确认」

#### F5. SQL 生成与修正（P0）

- 仅生成 `SELECT` / `WITH ... SELECT`
- 必须使用给定 schema 中的表字段名
- 大表查询需带过滤或 LIMIT（可配置）
- 执行失败或校验失败时，将错误回灌模型，最多重试 N 次（默认 3）
- 分析师模式可展示中间思考摘要（非原始 CoT，避免泄露）

#### F6. SQL 静态校验（P0）

校验项至少包括：

1. 语法可解析
2. 仅允许只读语句
3. 禁止多语句、禁止注释绕过（按引擎策略）
4. 表/字段在授权与召回范围内
5. 自动注入或校验 `LIMIT`（预览模式）
6. 危险函数/系统表拦截（可配置黑名单）

#### F7. 沙箱执行（P0）

| 项 | 要求 |
|----|------|
| 账号 | 只读账号，独立于生产写账号 |
| 超时 | 默认 10–30s 可配 |
| 行数 | 预览默认 100/200 行；全量需二次确认或导出任务 |
| 资源 | 最大扫描量/队列优先级可配 |
| 返回 | rows、row_count_estimate、latency_ms、query_id |

#### F8. 结果呈现与解释（P0）

- 表格预览 + 列类型
- 一键复制 SQL / 下载 CSV（权限内）
- 自然语言解释：用了哪些表、关键过滤、时间窗、是否去重
- 明确列出假设（如「默认按业务时区 Asia/Shanghai」）

#### F9. 多轮对话（P1）

- 继承上一轮的时间、对象、过滤条件
- 支持「按城市拆」「只要前 10」「换成上周」
- 会话可命名、可回看历史

#### F10. 权限与脱敏（P0 基础 / P1 增强）

- P0：库/表白名单 + 登录鉴权
- P1：行级条件自动注入、敏感列 mask、按角色可见指标

#### F11. 审计与反馈（P0）

记录：用户、时间、问题、召回 schema、最终 SQL、执行状态、行数、耗时、反馈（赞/踩/纠错）。

#### F12. 管理后台（P1）

- 元数据 CRUD / 导入
- 指标字典管理
- 权限配置
- 评测集与准确率看板
- 功能开关、限流配额

## 6. 关键用户流程

### 6.1 主流程

```text
用户提问
  → 鉴权与配额检查
  → 意图识别 / 槽位抽取
  → 是否需要澄清？ ——是→ 追问 → 等待用户补充
  → Schema / 指标检索（权限过滤后）
  → LLM 生成 SQL
  → 静态校验 ——失败→ 回灌修正（≤N）
  → 沙箱试跑 ——失败→ 回灌修正（≤N）
  → 组装回答（结果 + SQL + 口径）
  → 写审计日志
  → 用户可反馈 / 导出 / 追问
```

### 6.2 澄清流程

当出现以下情况必须澄清：

- 时间范围缺失或歧义（「最近」「同期」）
- 同名指标多个口径
- 过滤条件不可映射到字段
- 可能全表扫描且代价高

### 6.3 人审流程（v1.0）

```text
系统给出 SQL 预览与代价估计
  → 标记为「待确认」
  → 指定审批人（或自审）
  → 通过后执行全量/导出
  → 拒绝则回到对话修改
```

### 6.4 异常与降级

| 情况 | 处理 |
|------|------|
| LLM 超时 | 重试 1 次；仍失败则提示稍后重试 |
| 沙箱排队过长 | 告知预计等待，允许取消 |
| 连续 3 次生成失败 | 展示已尝试 SQL 与错误，建议缩小问题或转人工 |
| 元数据缺失 | 提示「未覆盖该主题域」，引导联系数据管理员 |

## 7. 技术架构

### 7.1 逻辑架构

```text
┌──────────────────────────────────────────────────────────┐
│                     接入层（Web / API）                    │
│              登录鉴权 · 会话 · 限流 · 审计写入              │
└────────────────────────────┬─────────────────────────────┘
                             │
┌────────────────────────────▼─────────────────────────────┐
│                 Orchestrator（问数编排器）                 │
│     意图 → 检索 → 生成 → 校验 → 执行 → 解释 → 反馈         │
└───────┬───────────────┬───────────────┬──────────────────┘
        │               │               │
        ▼               ▼               ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ LLM Gateway  │ │ Meta Service │ │ SQL Guard    │
│ 模型路由/重试 │ │ 表字段/指标  │ │ 解析/改写    │
│ Prompt 管理  │ │ 向量检索     │ │ 白名单校验   │
└──────────────┘ └──────────────┘ └──────┬───────┘
                                         │
                                         ▼
                               ┌──────────────────┐
                               │ Sandbox Executor │
                               │ 只读·限时·限行   │
                               └────────┬─────────┘
                                        │
                                        ▼
                               ┌──────────────────┐
                               │ 分析库 / 只读副本 │
                               └──────────────────┘
```

### 7.2 核心模块职责

| 模块 | 职责 |
|------|------|
| Orchestrator | 状态机编排、重试策略、会话上下文 |
| LLM Gateway | 多模型接入、超时、token 计量、敏感信息过滤 |
| Meta Service | 元数据存储、同义词、JOIN 图、向量索引 |
| Metric Layer | 官方指标定义与解析 |
| SQL Guard | sqlglot 解析、只读校验、LIMIT 注入、权限改写 |
| Sandbox Executor | 连接池、超时、取消、结果截断 |
| Audit & Feedback | 日志、评测、few-shot 挖掘 |
| Admin | 配置与运营后台 |

### 7.3 推荐技术选型（可替换）

| 层级 | 建议 |
|------|------|
| 前端 | React / Vue + 对话式 UI 组件 |
| 后端 | Python FastAPI（便于数据生态）或 Go |
| 编排 | 自研状态机；复杂后可引入 LangGraph 等 |
| LLM | 支持 tool calling 的商用/开源模型；可配置主备 |
| 元数据存储 | PostgreSQL |
| 向量检索 | pgvector / 专用向量库 |
| SQL 处理 | sqlglot |
| 执行引擎 | PostgreSQL / MySQL 只读副本；后续扩展 CH |
| 队列（可选） | Redis / 云队列，用于长查询与导出 |
| 观测 | OpenTelemetry + 日志平台 + 业务看板 |

### 7.4 Agent Tool 设计（MVP）

| Tool | 输入 | 输出 | 说明 |
|------|------|------|------|
| `search_schema` | query, top_k | 表/字段摘要列表 | 语义+关键字召回 |
| `get_table_detail` | table_name | 字段、类型、描述、关系 | 按需展开，控 token |
| `lookup_metric` | metric_name | 官方定义/表达式 | 命中则优先 |
| `validate_sql` | sql | ok / errors | 静态校验 |
| `run_sql_sandbox` | sql, limit | rows / error | 沙箱执行 |
| `ask_user` | question, options | 用户回答 | 澄清槽位 |

### 7.5 数据模型（逻辑）

**核心实体：**

- `User` / `Role` / `Permission`
- `Dataset` / `TableMeta` / `ColumnMeta` / `TableRelation`
- `MetricDef`（指标）
- `Synonym`（同义词）
- `Conversation` / `Message`
- `QueryRun`（一次生成与执行）
- `AuditLog` / `Feedback`
- `EvalCase` / `EvalRun`（评测）

**QueryRun 关键字段：** question、retrieved_schema、generated_sql、final_sql、status、error、row_count、latency_ms、model、retry_count。

### 7.6 安全架构要点

1. **网络**：应用与沙箱 DB 网络隔离；生产写库不可达。
2. **账号**：专用只读账号；禁用 DDL/DML。
3. **语句**：SQL Guard 强制只读与表白名单。
4. **数据**：敏感列脱敏；结果下载权限单独控制。
5. **模型**：prompt 不落敏感明文到第三方时需脱敏或私有化模型。
6. **审计**：不可篡改日志（至少追加写 + 权限分离）。

## 9. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 简单查询 P95 端到端 &lt; 60s；SQL 校验 &lt; 200ms |
| 可用性 | 核心问数链路月可用性 ≥ 99.5%（MVP 可放宽） |
| 并发 | MVP 支持 ≥ 20 并发会话；可水平扩展 Orchestrator |
| 准确性 | 见第 10 章评测指标 |
| 可观测 | 全链路 trace_id；模型/检索/执行分段耗时 |
| 可配置 | 模型、重试次数、LIMIT、超时、功能开关可配 |
| 国际化 | MVP 仅中文；SQL 方言可配 |
| 合规 | 支持数据分级；敏感操作可开人审 |

## 10. 效果评测与成功指标

### 10.1 产品指标

| 指标 | MVP 目标 | 说明 |
|------|----------|------|
| 周活跃问数用户 | 视客户基数定 | 采用率 |
| 自助解决率 | ≥ 50% | 无需转人工 |
| 平均首次出数时长 | &lt; 60s | 含模型与执行 |
| 用户满意度（赞比） | ≥ 60% | 有反馈样本 |

### 10.2 质量评测（离线黄金集）

| 指标 | MVP | v1.0 |
|------|-----|------|
| 表召回命中率 | ≥ 80% | ≥ 90% |
| SQL 可执行率 | ≥ 85% | ≥ 95% |
| 结果正确率 | ≥ 70% | ≥ 85% |
| 平均重试次数 | ≤ 1.5 | ≤ 1.0 |

评测集建设要求：覆盖单表过滤、聚合、多表 JOIN、时间窗口、同义词、歧义口径、无权限拒绝等类型。

| M3 准确率攻坚 | 2–3 周 | 指标字典、few-shot、追问策略 |
| M4 v1.0 | 3–4 周 | 脱敏、人审、管理后台、评测看板 |

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 元数据质量差 | 选表错误率高 | 先人工治理核心 10–30 张表；无描述不上线 |
| 口径歧义 | 信任崩塌 | 官方指标优先；不确定就追问 |
| LLM 幻觉编造字段 | 执行失败/错数 | 强约束只能用召回 schema；校验字段存在性 |
| 慢查询打满仓库 | 稳定性事故 | 超时、LIMIT、代价拦截、队列 |
| 敏感数据泄露 | 合规事故 | 脱敏、权限、审计、人审、模型侧脱敏 |
| 过度承诺「全自动」 | 预期失败 | 产品文案强调协助取数；复杂场景转人工 |

## 15. 附录

### 附录 A. 示例对话

**用户：** 查一下年龄大于 30 的用户，只要用户 ID、昵称和注册日期，按注册时间倒序，先看前 50 个。

**系统应：**

1. 召回 `dim_user` 等表  
2. 生成类似 SQL（示意）：

```sql
SELECT user_id, nickname, register_date
FROM dim_user
WHERE age > 30
ORDER BY register_date DESC
LIMIT 50;
```

3. 沙箱执行后返回表格 + 口径说明（年龄字段含义、是否含注销用户等假设）

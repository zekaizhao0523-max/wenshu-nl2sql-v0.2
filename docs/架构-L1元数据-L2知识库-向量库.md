## 1. 三层分工

```text
┌─────────────────────────────────────────────────────────────┐
│ L1 结构化元数据（MySQL）                                      │
│ 表/字段/JOIN/指标/同义词 —— 写 SQL 的「精确真相源」              │
└───────────────────────────────┬─────────────────────────────┘
                                │ 同步 embedding
┌───────────────────────────────▼─────────────────────────────┐
│ 向量库（Milvus / Qdrant）                                     │
│ L1 + L2 的语义检索索引；只存 vector + payload，不存业务明细     │
└───────────────────────────────┬─────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────┐
│ L2 知识库文档（MySQL kb_* + 文件）                             │
│ 指标白皮书、业务规则、FAQ —— 复杂口径与例外说明                  │
└─────────────────────────────────────────────────────────────┘

Hive 数仓：仅存业务明细，沙箱只读执行 SQL，不参与元数据存储。
```

| 层级 | 存什么 | 检索后用来干什么 |
|------|--------|------------------|
| **L1** | 表、字段、类型、JOIN、指标 SQL、同义词 | 选表选字段、拼 JOIN、套指标模板、校验 |
| **L2** | Wiki/PDF/MD 切 chunk | 补充复杂规则、例外、解释 |
| **向量库** | embedding + `{type, object_id, ...}` | 用户问题 → Top-K 候选 |

## 2. L1 表结构说明

完整 DDL 见 `sql/metadata_schema.sql`。

### 2.1 实体关系

```text
table_meta 1 ── N column_meta
table_meta N ── N table_meta   （通过 table_relation 表达 JOIN）
metric_def   （独立，related_tables 指向多张表）
synonym      ──▶ table / column / metric（多对一）

kb_document 1 ── N kb_chunk
vector_index_log 记录 L1/L2 条目与向量库的映射
```

### 2.2 示例数据

**table_meta**

| table_id | db_name | table_name | cn_name | domain |
|----------|---------|------------|---------|--------|
| T001 | ods | dim_user | 用户维度表 | 用户 |
| T002 | ods | fact_order | 订单事实表 | 交易 |

**column_meta（节选）**

| column_id | table_id | column_name | data_type | description |
|-----------|----------|-------------|-----------|-------------|
| C001 | T001 | user_id | bigint | 用户唯一ID |
| C002 | T001 | age | int | 用户年龄，周岁 |
| C010 | T002 | order_amt | decimal | 订单实付金额，元 |

**table_relation**

| left | right | join_type |
|------|-------|-----------|
| ods.fact_order.user_id | ods.dim_user.user_id | LEFT JOIN |

**metric_def**

| metric_id | metric_name | aliases | sql_template |
|-----------|-------------|---------|--------------|
| M001 | DAU | ["日活","日活跃用户数"] | `SELECT COUNT(DISTINCT user_id) FROM ods.fact_login WHERE dt='${date}'` |

**synonym**

| term | target_type | target_id |
|------|-------------|-----------|
| 会员 | table | T001 |
| 年纪 | column | C002 |
| 日活 | metric | M001 |

## 3. L2 知识库结构

| 表 | 作用 |
|----|------|
| `kb_document` | 原始文档登记（标题、路径、主题域） |
| `kb_chunk` | 文档按 300–800 字切 chunk，供 embedding |

**适合放 L2 的内容：**

- 《用户指标口径白皮书》
- 「大促期间 DAU 统计例外规则」
- 历史优质问答 / 分析师备注
- 财务口径与数仓口径差异说明

**不适合只放 L2、必须放 L1 的内容：**

- 字段类型、JOIN 键、指标标准 SQL、敏感字段标记

## 4. 向量库 payload 设计

Collection 名称建议：`wenshu_knowledge`

每条向量记录：

```json
{
  "id": "column:T001.C002",
  "vector": [0.23, -0.11, "..."],
  "payload": {
    "object_type": "column",
    "object_id": "C002",
    "db": "ods",
    "table": "dim_user",
    "column": "age",
    "domain": "用户",
    "priority": 10
  }
}
```

| object_type | id 规则 | priority（合并排序用） |
|-------------|---------|------------------------|
| `metric` | `metric:{metric_id}` | 100 |
| `column` | `column:{column_id}` | 80 |
| `table` | `table:{table_id}` | 60 |
| `join` | `join:{relation_id}` | 50 |
| `doc_chunk` | `doc:{chunk_id}` | 40 |

## 5. 检索合并逻辑

### 5.1 在线检索流程

```text
用户问题 Q
  │
  ├─① 向量检索（Top-K=30，object_type 不限）
  │
  ├─② 同义词精确匹配 synonym.term = 抽词(Q)
  │
  ├─③ 关键字检索（可选，BM25 / LIKE 字段名表名）
  │
  ▼
合并去重（同一 table/column 保留最高分）
  │
  ├─ 加权：final = vec_score * type_weight + synonym_boost + keyword_boost
  │         type_weight: metric=1.2, column=1.0, table=0.8, doc_chunk=0.6
  │
  ▼
权限过滤（用户不可见的 db/table 剔除）
  │
  ▼
JOIN 扩展：若命中 fact_order 且涉及用户属性，自动补 dim_user（table_relation）
  │
  ▼
回表 L1/L2 拉完整信息
  │
  ▼
组装 prompt（见 5.3）
```

### 5.2 合并伪代码

```python
def retrieve_schema(question: str, user, top_k: int = 30) -> RetrievalResult:
    vec_hits = vector_search(embed(question), limit=top_k)
    syn_hits = synonym_lookup(extract_terms(question))
    kw_hits = keyword_search(question, limit=20)

    merged = merge_and_rerank(vec_hits, syn_hits, kw_hits)
    merged = filter_by_permission(merged, user)
    merged = expand_join_neighbors(merged)          # 读 table_relation
    full = fetch_l1_l2_metadata(merged)

    return build_prompt_context(full)
```

### 5.3 组装进 prompt 的结构

```text
## 官方指标（优先使用）
- DAU：当日登录去重 user_id。SQL 模板：...

## 可用表结构
### ods.dim_user（用户维度表）
- user_id (bigint): 用户唯一ID
- age (int): 用户年龄，周岁

### ods.fact_order（订单事实表）
- order_amt (decimal): 订单实付金额

## 常用 JOIN
- ods.fact_order.user_id = ods.dim_user.user_id

## 补充业务规则（来自知识库）
- 大促期间 DAU 需排除 test 前缀账号（来源：指标白皮书 §3.2）

## 约束
- 仅可使用上述表与字段
- 方言：Hive SQL
- 大表必须带分区条件

## 用户问题
{question}
```

### 5.4 L1 vs L2 优先级

| 场景 | 优先来源 |
|------|----------|
| 「昨天 DAU」 | L1 `metric_def` |
| 「年龄>30 的用户订单」 | L1 column + table_relation |
| 「大促 DAU 要不要算测试号」 | L2 kb_chunk，若无则澄清 |
| L1 与 L2 口径冲突 | **以 L1 metric_def 为准**，L2 仅作备注 |

## 6. 与 Hive 的关系

| 组件 | 角色 |
|------|------|
| Hive Metastore | L1 的**自动发现来源**（库表字段注释） |
| MySQL 元数据库 | L1/L2 **真相源**，人工可编辑补全 |
| 向量库 | 检索索引，随 L1/L2 变更增量更新 |
| Hive 沙箱 | **仅执行** LLM 生成的 SQL，不存元数据 |

## 7. 运维与更新

| 事件 | 动作 |
|------|------|
| Hive 新增表/字段 | `sync_hive_metadata.py` → 更新 L1 → 增量 re-embed |
| 人工改 description/同义词 | 更新 L1 → 对比 hash → 仅变更项 re-embed |
| 上传新 Wiki | 切 chunk 入 L2 → embed doc_chunk |
| 表下线 | L1 `is_enabled=0` → 向量库 delete point |

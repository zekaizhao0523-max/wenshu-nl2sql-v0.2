# 问数平台使用说明

| 属性 | 内容 |
|------|------|
| 版本 | v1.1 |
| 更新日期 | 2026-08-28 |
| 适用对象 | 平台使用者、评测同学、二次开发 |

本文说明：**如何启动平台**、**各页面能做什么**、**如何通过 API 调用问数 Agent**，以及**从 0 到能问数的推荐流程**。

## 1. 环境准备

### 1.1 依赖服务

| 服务 | 用途 | 典型配置 |
|------|------|----------|
| **业务 MySQL（RAW）** | 真实业务表，只读查询 | `MYSQL_*` / `RAW_MYSQL_*` |
| **元数据 MySQL（META）** | L1 表/列/JOIN/指标/同义词 | `META_MYSQL_*` |
| **Qdrant** | Schema 向量索引 | `QDRANT_URL`、`QDRANT_COLLECTION` |
| **Embedding** | 本地模型或 OpenAI 兼容 API | `EMBEDDING_PROVIDER` |
| **LLM** | 选列、QueryPlan、SQL 生成 | Ollama 或 `LLM_*` |

### 1.2 安装与启动

```bash
pip install -r requirements.txt
cp .env.example .env   # 填入本地连接与模型
python scripts/run_platform.py
```

浏览器打开 **http://127.0.0.1:8765**。

本地一键栈（可选）：`scripts/start_local_stack.ps1`（MySQL 3307 + Qdrant 6333）。

> UI 中保存的 `.wenshu/connections.json`、`.wenshu/model_settings.json` **优先于** `.env`。

## 2. 管理台功能一览

左侧导航对应以下能力：

| 页面 | 功能 | 典型操作 |
|------|------|----------|
| **连接配置** | 配置 RAW / META / Qdrant | 测试连接 → 保存 |
| **元数据同步** | init → scan → sync 流水线 | 首次 init；日常 scan 后去编辑 |
| **元数据编辑** | staging 审核、L1 表列注释 | 补 description、synonyms、sample_questions |
| **知识库** | L2 文档、chunk、指标、同义词 | 维护业务口径与 JOIN |
| **向量库同步** | 增量/全量 embedding | sync 到 L1 后必须 index |
| **召回测试** | 单题 Schema 召回调试 | 看定表、列池、S1/S2、M-Schema |
| **问数 Agent** | 端到端 NL2SQL | 输入问句 → 澄清/计划/SQL/执行/解读 |
| **任务历史** | 后台任务记录 | 查看 scan/index 等任务状态 |

## 3. 推荐工作流（从 0 到能问数）

```text
① 连接配置
   原始库 → 元数据库 → 向量库 → 测试连接 → 保存

② 元数据同步（仅首次）
   初始化元数据表（init）

③ 元数据同步
   扫描业务库（scan）→ 进入「元数据编辑」审核

④ 元数据编辑
   补全表/字段中文说明、同义词、示例问法 → 保存

⑤ 元数据同步
   「同步到 L1」（全库或单表）

⑥ 向量库同步
   全量或增量构建索引（index）

⑦ 召回测试
   用黄金集样例问句验证 Table/Column 是否命中

⑧ 问数 Agent
   自然语言取数；敏感查询可走人工审批
```

**关键原则**：L1 是真相源；改注释或 JOIN 后必须 **重新 index**，否则召回仍用旧向量。

## 4. 召回测试页

入口：**召回测试** 或 `POST /api/search/test`。

### 4.1 输入项

| 字段 | 说明 |
|------|------|
| 问句 | 自然语言问题 |
| Evidence | 可选业务补充（口径、时间范围等） |
| 关键词模式 | `auto` / `llm` / `rule`（见 [配置与参数说明](./配置与参数说明.md)） |
| 澄清闸门 | 缺槽时返回 `need_clarify`，需带 `clarify_answers` 再请求 |
| 选列 S1/S2 | 是否对列池做 LLM 两轮精选 |

### 4.2 输出解读

- **expanded_tables**：定表 + JOIN 扩展后的表集合（Table Hit 口径）
- **columns / s1_columns / s2_columns**：列池与精选结果
- **mschema**：供下游 SQL 使用的结构化 schema 文本

详细指标与实验设计见 [召回测试实验操作手册](./召回测试实验操作手册.md)。

## 5. 问数 Agent

入口：**问数 Agent** 页、`POST /api/agent/query`、`POST /api/agent/approve`。

### 5.1 端到端流程

```text
澄清闸门 → Schema 召回 → QueryPlan → LogicalPlan → 计划校验
    → SQL 生成 → 静态校验 → 敏感检测 → [人工审批] → 只读沙箱 → 结果解读
```

编排实现：`wenshu/services/agent/graph.py`（LangGraph）。技术细节与 icecoding 对照见 [问数Agent技术说明](./问数Agent技术说明.md)。

### 5.2 Web 使用

1. 在「问数 Agent」输入问句（可选 Evidence）
2. 勾选「仅生成 SQL，不执行沙箱」可跳过执行（等同 `AGENT_SKIP_SANDBOX=1`）
3. 若返回 **需要澄清**：按提示补全槽位后再次运行
4. 若返回 **需要审批**：在界面批准/拒绝，或调用 approve API

### 5.3 API 示例

**发起查询：**

```bash
curl -X POST http://127.0.0.1:8765/api/agent/query \
  -H "Content-Type: application/json" \
  -d '{"query": "年龄大于30的客户有多少", "evidence": ""}'
```

**人工审批恢复**（`status=need_approval` 时）：

```bash
curl -X POST http://127.0.0.1:8765/api/agent/approve \
  -H "Content-Type: application/json" \
  -d '{"trace_id": "<上一步返回的 trace_id>", "approved": true}'
```

### 5.4 返回状态

| status | 含义 | 下一步 |
|--------|------|--------|
| `need_clarify` | 缺时间/对象等槽位 | 带 `clarify_answers` 再 query |
| `need_approval` | 敏感或高风险 SQL | 调用 approve |
| `completed` | 成功（含仅生成 SQL） | 查看 `generated_sql`、`execution_result`、`final_answer` |
| `blocked` | 规则拦截 | 查看 `blocked_reason` |
| `failed` | 计划/SQL/执行失败 | 查看 `trace_steps`、错误信息 |

### 5.5 仅要 M-Schema / Prompt

不跑完整 Agent 时可用：

| API | 作用 |
|-----|------|
| `POST /api/nl2sql/mschema` | 问句 → M-Schema |
| `POST /api/nl2sql/prompt` | 问句 → 完整 NL2SQL Prompt |

## 6. 评测与回归

### 6.1 仅 Schema 召回

```bash
python evals/scripts/run_recall_eval.py --golden evals/golden/recall_demo.jsonl
```

### 6.2 召回 + SQL 联合评测（StructAcc / ResultAcc）

```bash
# 可选：为黄金集写入 gold_sql
python evals/scripts/attach_gold_sql.py --golden evals/golden/recall_v2_dwd.jsonl

python evals/scripts/run_sql_eval.py \
  --golden evals/golden/recall_v2_dwd.jsonl \
  --keyword-mode rule \
  --column-select
```

报告输出到 `evals/reports/`。指标说明见 [evals/golden/README.md](../evals/golden/README.md) 与 [召回测试实验操作手册](./召回测试实验操作手册.md#6-sql-联合评测structacc--resultacc)。

### 6.3 切换 SQL 生成路径做对比

默认 **icecoding 路径**（M7 多候选 + AST 打分 + M8/M10 重试）。要试 XiYan 执行选优流程：

```bash
# PowerShell
$env:AGENT_SQL_XIYAN_PIPELINE="1"
python evals/scripts/run_sql_eval.py --golden evals/golden/recall_v2_dwd.jsonl
```

参数全集见 [配置与参数说明](./配置与参数说明.md)。

## 7. 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 召回为空 / 集合不存在 | 未 index | 向量库同步页全量 index |
| 定表对、列不对 | L1 列说明弱 / 未开 S2 | 补 column description；`SCHEMA_COLUMN_SELECT=1` |
| SQL 语法错 | 计划与 schema 不一致 | 看 `query_plan`；调 `AGENT_PLAN_LLM` 或修召回 |
| 执行超时 | 大表无过滤 | 检查 WHERE；调 `AGENT_SQL_TIMEOUT_MS` |
| 一直要审批 | 敏感规则命中 | `AGENT_APPROVAL_ENABLED=0` 仅本地调试 |
